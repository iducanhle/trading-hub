## Known issues

From the backend (details in [PROGRESS-backend.md](PROGRESS-backend.md) and [DATA-SOURCES.md](DATA-SOURCES.md)); the UI must render these as `—`, never invent values:
- EU revenue estimates for past quarters are missing; EU revenue actuals exist only for the last 4 quarters.
- Report times are often `UNKNOWN` (about 70% of US calendar events); reactions then use the UNKNOWN rule with `timeAssumed = true`.
- Small caps often lack analyst estimates.
- EU peers: at most 5. EU news has no source name or image.
- `logoUrl` in search results is filled only for stocks whose profile is already cached. Google's favicon service (a logo fallback) returns a generic globe instead of an error, so such logos never fall back to initials.

Frontend:
- **The Firebase web-app keys are placeholders** (`apiKey`, `appId`, `messagingSenderId` in both environment files) until the web app is registered in the Firebase console. Until then `npm start` cannot sign in; mock mode and the emulator configuration work.
- The Material theme uses CSS `light-dark()` (Material's `color-scheme` theme type): Safari/iOS 17.5+, Chrome 123+, Firefox 120+. Older browsers would show broken colours.

## Decisions

- **2026-09-30 — The live values are known and used:** Firebase project `tradiqo`, backend `https://tradiqo.duckdns.org` (see PROGRESS-backend "Live deployment"). They go into `environment.prod.ts` and `.firebaserc` instead of `YOUR_SUBDOMAIN`/project placeholders. The Firebase web-app keys (`apiKey`, `appId`, `messagingSenderId`) do not exist until the web app is registered, so they stay `PLACEHOLDER`.
- **2026-09-30 — Commits go straight to `main`, not pushed** (same as the backend). Pushing is left to the owner, because a push to `main` triggers the deploy workflows.
- **2026-09-30 — Versions** (npm, 2026-09-30): Angular/CLI/Material 22.2.0, TypeScript 6.0, Tailwind 4.3, Firebase JS SDK 12.19, lightweight-charts 5.2.1, angular-eslint 22.5, Vitest 5 (the CLI default).
- **2026-09-30 — No AngularFire:** its latest release (20.1.0) supports Angular 20 only (21 is a release candidate). The modular Firebase SDK is wrapped in injectable services instead, as the prompt allows.
- **2026-09-30 — Firestore is loaded lazily** (dynamic `import('firebase/firestore')` on first use, right after sign-in). It is the largest part of the SDK; keeping it out of the initial bundle keeps the first paint fast. Material's snack bar is lazy for the same reason (`NotifierService`), and no Material module is imported by `app.config.ts`.
- **2026-09-30 — Resource APIs:** `resource`/`rxResource`/`httpResource` are `@publicApi` (stable) in Angular 22, so feature pages use them.
- **2026-09-30 — Reactive forms, not Signal Forms**, for the auth and settings forms: Material form fields integrate with them without adapters.
- **2026-09-30 — Material theme via `theme-type: color-scheme`:** one set of `light-dark()` tokens, switched by `color-scheme`, so Material and Tailwind's `.dark` variant can never disagree. The cost is the browser floor noted in Known issues.
- **2026-09-30 — Tailwind preflight is kept:** Tailwind 4 puts it in a cascade layer and Material's CSS is unlayered, so Material always wins over preflight. Tailwind is used for layout around Material components, not to restyle them.
- **2026-09-30 — Icons are inline SVG paths** (Material Symbols Outlined, Apache-2.0) generated into `shared/icon/icon-paths.ts`: no icon font download, no flash of ligature text, works offline. The text font is the system stack (SF Pro on iOS, Roboto on Android), so no web font is downloaded either.
- **2026-09-30 — Number and date locale:** the UI is English. Numbers use en-US conventions (compact `$8.4B`, `€312M`; en-GB would print `€312m`, `$8.4bn`). Dates use the device's English variant (`navigator.languages`), else en-GB (day before month); relative labels ("Tomorrow", "In 3 days") are English.
- **2026-09-30 — Google sign-in:** popup when the pointer is fine (desktop), redirect on touch devices and in the installed app. `authDomain` is set at runtime to the Hosting domain the app is served from (`*.web.app` / `*.firebaseapp.com`), Firebase's option 1 for browsers that partition third-party storage; `environment.prod.ts` says `tradiqo.web.app`, `environment.ts` the firebaseapp.com domain for localhost. The popup/redirect resolver is passed per call, so normal app starts never load the auth iframe.
- **2026-09-30 — The allowlist check never blocks on a network failure:** only a real 403 leads to `/no-access`; offline, the app opens with cached data and inline errors.
- **2026-09-30 — `UserDataGateway` abstraction** between the services and Firestore, so mock mode and unit tests run without Firebase. The user document is created only when the server (not the local cache) reports that it does not exist.
- **2026-09-30 — Undo of an unfollow restores the original `followedAt`**, so the Firestore rules accept any timestamp for `followedAt` (not only `request.time`).
- **2026-09-30 — Mock fixtures are dated around the week of 28 Sep 2026 and shifted by whole weeks** to the current week at runtime, so they never go stale and weekdays stay weekdays. Price bars are generated (seeded per symbol) instead of stored, which keeps the fixtures small and covers every range.
- **2026-09-30 — The API is on another origin** (`tradiqo.duckdns.org`), so the service worker's `api` data group lists the absolute URL as well as `/api/**`.
- **2026-09-30 — Guards inject everything before their first `await`** (`inject()` only works synchronously); a unit test caught the original version.
- **2026-09-30 — Active tab from a URL signal:** with zoneless OnPush, `routerLinkActive.isActive` does not re-render the template.
