**Decisions (from the contract, relevant to the UI)**
- **2026-10-02 —** Periods are sent as `from`/`to` days plus `tz` (the device's IANA zone); All = no `from`/`to`.
- **2026-10-02 —** `unrealizedPnl` is as of now; `totalPnl` includes it only for All (`includesUnrealized`). `totalPnlPct` is `null` for a period, so P/L % sorting puts those last.
- **2026-10-02 —** Prices (`averageCost`, `currentPrice`, trade `price`) are in the instrument currency; every other amount is in `accountCurrency`.
- **2026-10-02 —** When `GET /api/t212/status` answers 503 `T212_NOT_CONFIGURED`, Settings shows "not available on this server" instead of the connect form.
- **2026-10-02 —** The connect form clears the key and secret on every submit, also when it fails, so the key never outlives the request (the user pastes it again after an error).
- **2026-10-02 — Six tabs in the bottom bar, all with labels:** measured at 360 px in Czech (the longest language): each tab is 60 px and the widest label ("Sledované") 56 px, with no horizontal overflow, so neither shorter labels nor active-only labels are needed.
- **2026-10-02 —** The portfolio sub-tabs sit in the sticky header (they scroll sideways on narrow phones); the period selector is at the top of the content, so the sticky header stays 96 px on a phone instead of ~170 px.
- **2026-10-02 —** Default period is All (the only one with unrealized P/L and percentages). Periods end today and start the same day a month/3 months/a year back plus one day (`shiftMonths` clamps to month end; the shared `addMonths` returns the 1st and does not fit).
- **2026-10-02 —** Buy/Sell and Open/Closed have their own i18n meaning, so Czech uses the nouns Nákup/Prodej (the analyst ratings keep the verbs Koupit/Prodat).
- **2026-10-02 —** Server error messages are English; the connect form shows its own translated text per error code and only takes the list of missing permissions from the server's message.
- **2026-10-03 — Open positions on the Overview,** grouped as in the Trading 212 app: a pie is one row and expands in place (a disclosure button with `aria-expanded`, not a modal); its instruments link to their detail like the other rows.
- **2026-10-03 — Chart ranges and toggles:** the stock page has 1D 1W 1M 3M 6M 1Y 3Y 5Y, the position dialog 1D 1W 1M 2M 3M 6M 1Y 3Y 5Y (fits 360 px). 1D bars are placed by time shifted to the device's zone (the chart library shows UTC); trade markers are off on intraday bars (they mark days). Measure works on intraday bars too (2026-10-05): it shows clock times and a length in min / h instead of dates and days. The stock page has remembered toggles for the position lines (only with an open position in the chart's currency), earnings markers and my trades; the dialog has none.
- **2026-10-03 — Position dialog:** tapping an open position on the Overview opens a dialog (not the page) with a closing-price line chart, a dashed line at the average cost and a solid line at the current price (both kept in the price scale), then P/L and position details; links to the stock page and to the full position. The lines are drawn only when the chart and the position are in the same currency (pence quotes are shown in pounds); unmapped instruments get no chart.
- **2026-10-03 — Rate of return and type scale:** the Overview's second figure is `rateOfReturnPct` ("Míra výnosu", the money-weighted return Trading 212 shows), not `totalPnlPct` (÷ all buys, near 0 % for an account that trades a lot). Figures sized to the Trading 212 app: hero 40 px (`md` 34 px) with an 18 px currency, summary figures 15 px semibold, section titles `text-lg`; list rows use 15 px medium names, 15 px semibold amounts and 12.5 px medium P/L.
- **2026-10-03 — Asset allocation** (Overview, under best/worst): a squarified treemap (`treemap.ts`) of `GET /api/t212/allocation`, area = share of the open positions' value, tile colour = today's price change (`gain/loss-container`, grey without a quote). The 9 largest get tiles, the rest share a "…" tile (at least 4 % of the area so it stays tappable); what a tile shows (logo, ticker, change) depends on its size. A tile opens the position dialog; "See all" expands the full list in place. **2026-10-04:** today's change comes from `GET /api/t212/allocation/day-changes` in a second request (cached 45 s in `ApiService`), so the treemap draws right away and colours in when the quotes arrive.
- **2026-10-04 — Unrealized switch on the Stocks tab turned off** (commented out in `portfolio-stocks.ts`, with what to restore): the tab shows realized P/L only, in every period. Before that it was limited to All, because: In a shorter period the list holds only stocks with a trade, dividend or fee in it, and the unrealized is the whole holding's as of now, so "with unrealized" gave a sum that meant nothing (a held stock without activity was left out, an active one counted its whole gain). Outside All the switch is replaced by an info line of the same size (42 px) and the rows, total, best/worst and position dialog use realized only; the remembered choice comes back on All. The Overview shows the unrealized ("as of now") next to the total P/L.
- **2026-10-04 — "Fees" fields became "Including fees" (ⓘ `includingFees`)**, like the Stocks tab card: the trade dialog shows the value before fees as the hero and Trading 212's value (fees included) in the row; the position summary ends in "Total" (sum before fees) and "Including fees" (= the hero total); the Trades tab card shows realized − fees. The FX fees row (instrument page) and the account fees (Dividends & cash) stay as amounts.

## Known issues

From the backend (details in [PROGRESS-backend.md](PROGRESS-backend.md) and [DATA-SOURCES.md](DATA-SOURCES.md)); the UI must render these as `—`, never invent values:
- EU revenue estimates for past quarters are missing; EU revenue actuals exist only for the last 4 quarters.
- Report times are often `UNKNOWN` (about 70% of US calendar events); reactions then use the UNKNOWN rule with `timeAssumed = true`.
- Small caps often lack analyst estimates.
- EU peers: at most 5. EU news has no source name or image.
- Logos: the provider (Finnhub) logo when the profile is stored, else a square logo from Parqet/Elbstream by ticker (`assets.parqet.com/logos/symbol/{ticker}`, free with an attribution link, which is in Settings → About; 404 for unknown tickers, which the web app shows as initials). The old fallbacks (FMP ticker images, Google favicons) are retired, and stored copies are ignored by `Logos`.

Frontend:
- The Material theme uses CSS `light-dark()` (Material's `color-scheme` theme type): Safari/iOS 17.5+, Chrome 123+, Firefox 120+. Older browsers would show broken colours.
- **Not yet verified against the real Firebase project** (the web app is not registered yet): Google sign-in (popup and redirect), the verification email and the password-reset email, deployed rules and Hosting. The same code paths ran against the Auth/Firestore emulators with email/password, and the checklist in DEPLOYMENT-frontend.md step 9 covers the rest.
- The calendar was checked with real data only as an empty week (the backend's calendar job did not run in the fresh emulator database); its rendering was verified with the mock data, which has the same contract shape.
- The backend caches each user's follows for a minute: a stock followed on another device appears on Followed at once (from Firestore) but gets its date from the backend within about a minute (the page refetches after 1.5 s and 65 s).
- The service worker caches API responses by URL, not by user; with two users on separate devices this never mixes data, but after signing out and in as someone else on the same device, offline mode could show the previous user's cached Followed list.
- Pull-request preview channels can't sign in with Google or reach the API (their addresses are not in the redirect URIs or the backend's CORS list); they are for looking at layout changes.
- Logos come from third-party hosts (Finnhub, Parqet) and are not cached by the service worker (opaque responses); offline, they fall back to initials only if the browser cache has none.

The trade, dividend and position dialogs add a "Traded in USD" pill, the amount as it settled ("In USD"), the trade-day exchange rate (with the `tradeDayRate` ⓘ) and the result in that currency; timeline rows add the settled amount to the meta line.

Everything is still computed in the account currency; only the printed text converts: amounts are marked with the `acct` pipe (`accountCurrency()`), and `formatPrice` / `splitMoney` / `formatSignedMoney` / `formatCompact` convert marked ones via the `displayConversion` signal (`DisplayCurrencyService`). Share prices and settled amounts in other currencies are not marked, so they stay as they are; the history chart axis stays in the account currency. The Firebase web-app keys (`apiKey`, `appId`, `messagingSenderId`) do not exist until the web app is registered, so they stay `PLACEHOLDER`.

- **2026-09-30 — Versions** (npm, 2026-09-30): Angular/CLI/Material 22.2.0, TypeScript 6.0, Tailwind 4.3, Firebase JS SDK 12.19, lightweight-charts 5.2.1, angular-eslint 22.5, Vitest 5 (the CLI default).
- **2026-09-30 — No AngularFire:** its latest release (20.1.0) supports Angular 20 only (21 is a release candidate). The modular Firebase SDK is wrapped in injectable services instead, as the prompt allows.
- **2026-09-30 — Firestore is loaded lazily** (dynamic `import('firebase/firestore')` on first use, right after sign-in). It is the largest part of the SDK; keeping it out of the initial bundle keeps the first paint fast. Material's snack bar is lazy for the same reason (`NotifierService`), and no Material module is imported by `app.config.ts`.
- **2026-09-30 — Resource APIs:** `resource`/`rxResource`/`httpResource` are `@publicApi` (stable) in Angular 22, so feature pages use them.
- **2026-09-30 — Reactive forms, not Signal Forms**, for the auth and settings forms: Material form fields integrate with them without adapters.
- **2026-09-30 — Material theme via `theme-type: color-scheme`:** one set of `light-dark()` tokens, switched by `color-scheme`, so Material and Tailwind's `.dark` variant can never disagree. The cost is the browser floor noted in Known issues.
- **2026-09-30 — Tailwind preflight is kept:** Tailwind 4 puts it in a cascade layer and Material's CSS is unlayered, so Material always wins over preflight. Tailwind is used for layout around Material components, not to restyle them.
- **2026-09-30 — Icons are inline SVG paths** (Material Symbols Outlined, Apache-2.0) generated into `shared/icon/icon-paths.ts`: no icon font download, no flash of ligature text, works offline. The text font is the system stack (SF Pro on iOS, Roboto on Android), so no web font is downloaded either.
- **2026-09-30 — Number and date locale:** the UI is English. Numbers use en-US conventions (compact `$8.4B`, `€312M`; en-GB would print `€312m`, `$8.4bn`). Dates use the device's English variant (`navigator.languages`), else en-GB (day before month); relative labels ("Tomorrow", "In 3 days") are English.
- **2026-09-30 — Google sign-in:** popup when the pointer is fine (desktop), redirect on touch devices and in the installed app. `authDomain` is set at runtime to the Hosting domain the app is served from (`*.web.app` / `*.firebaseapp.com`), Firebase's option 1 for browsers that partition third-party storage; `environment.prod.ts` says `tradiqo.web.app`, `environment.ts` the firebaseapp.com domain for localhost. The popup/redirect resolver is passed per call, so normal app starts never load the auth iframe.
